# 需求规格说明书：系统安全边界、状态一致性与交互体验加固 (013-system-resilience-ux)

## 1. 概述与背景

在前期 001~012 迭代中，VideoCut 实现了“口播自然句切分、MiniMax 云端 ASR、大模型行业专名词纠偏、双层 65% 黄金分镜编排、实战封面生成与抖音违禁词合规清洗”的全链路闭环。

然而在针对全项目的全链路审计中，发现系统在**数据生命周期与残留、故障容错与清理、前后端状态同步断裂、以及真实等待交互反馈**四大关键防线存在结构性短板：
1. **数据生命周期缺陷**：素材删除时未级联清理磁盘任务目录，导致 `_heal_from_disk()` 在软件重启后将已被删除的工程“幽灵复活”；
2. **故障容错短板**：云端 ASR 单次请求零重试；批量混剪无法中途取消、单项失败不可重试、崩溃后残留死锁僵尸批次；
3. **状态同步断裂**：后端在 `editor.py` 内部维护了 `_pipeline_progress`（15%~100%），前端 `VideoEditor.tsx` 却完全未调用轮询，页面死等数十秒假死；缺乏 `AbortController` 导致快速切换素材时异步返回相互覆盖；
4. **真实交互黑盒**：长耗时任务无步骤进度条指示器；批量混剪卡片未消费 `item.progress`；错误信息被前端静态文案吞噬。

本特性的目标是系统性根治上述隐患，构建稳健、可逆、具备真实反馈的高健壮性桌面端剪辑系统。

## 2. 核心用户故事 (User Stories)

### 故事 1：干净的数据清理与无幽灵复活 (Data Integrity & No Ghosts)
* **作为一个** 短视频创作者，
* **当我** 在素材库或剪辑台删除了一个口播素材或剪辑工程时，
* **我希望** 磁盘上对应的压制视频、临时音频、封面图片及任务清单目录被 100% 干净清理；
* **以便于** 释放宝贵的磁盘空间，且在应用重启后该工程绝对不会被系统“错误自愈”重新复活。

### 故事 2：具备韧性的网络请求与批量任务管控 (Resilience & Task Control)
* **作为一个** 高频使用批量混剪的运营教练，
* **当我** 遇到偶发网络微弱波动时，云端 ASR 识别能自动重试恢复，而不是直接抛错崩溃；
* **当我** 误操作提交了一批混剪视频时，我能一键“取消批次”，释放电脑 CPU/GPU 算力；
* **当** 批量任务中有个别视频因偶发原因失败时，我能一键“重试失败项”，无需整批重来；即使电脑断电重启，队列中的任务状态也能被安全重置为“已中断”，不再卡死在假运行态。

### 3. 故事 3：清晰明了的长任务进度与阶段感知 (UX Progress & Transparency)
* **作为一个** 等待视频处理的用户，
* **当我** 点击“⚡ 智能初剪与纠偏”时，
* **我希望** 界面展示生动的 4 步阶段指示条（音频抽取 15% → 语音转写 45% → 大模型纠偏 70% → 分镜决策 90% → 完成），并能获知大模型是否已经开始输出；
* **以便于** 我清楚系统正在哪一步真实运转，避免误以为程序假死而烦躁刷新。

## 3. 功能需求与成功指标 (Functional Requirements & KPIs)

### 3.1 数据生命周期与冲突防线 (P0)
* **FR-101 (级联清理闭环)**：`storage_service.delete_material(id)` 删除口播素材时，必须强制触发 `_cleanup_project_files`，物理删除 `storage/tasks/<task_dir>/` 及关联成片文件。
* **FR-102 (自愈校验防线)**：`project_storage_service._heal_from_disk()` 扫描任务目录时，必须强校验 `talking_head_id` 是否真实存在于 `materials` 表；若素材已不存在，就地清空该任务目录，严禁恢复写入 SQLite。
* **FR-103 (前端防竞态守卫)**：`VideoEditor.tsx` 在发起 `analyzeAndCutVideo` 及 `loadProjectForMaterial` 时绑定 `AbortController`；当用户切换素材或离开页面时，立即取消正在进行的网络回调，禁止覆盖当前视图。

### 3.2 故障容错、重试与队列管控 (P1)
* **FR-201 (ASR 指数退避重试)**：`asr_runner.transcribe_minimax` 引入重试装饰器，针对 5xx、429、Timeout 等瞬时错误执行至多 3 次重试（退避间隔 1s、2s、4s）。
* **FR-202 (批量任务取消)**：新增 `POST /api/v1/batch/jobs/{job_id}/cancel` 接口，支持取消后台正在排队或执行的并发压制 Task。
* **FR-203 (批量单项重试)**：新增 `POST /api/v1/batch/jobs/{job_id}/retry-failed` 接口，仅将 `status == 'failed'` 的条目重新压入执行槽位。
* **FR-204 (启动自愈清理)**：后端应用生命周期 `lifespan` 启动时，自动巡检 `batch_jobs` 表，将残留为 `running` / `queued` 的历史批次统一自愈更新为 `interrupted`。

### 3.3 交互体验与进度可视化 (P2)
* **FR-301 (初剪四阶段步骤指示器)**：前端 `VideoEditor.tsx` 在初剪期间启动 800ms 定时轮询 `fetchProjectProgress`，渲染带有动态光效的四阶段进度条组件（抽取音频 15% → ASR识别 45% → AI专词纠偏 70% → 双层分镜 90%）。
* **FR-302 (批量混剪进度条与错误透出)**：`BatchCut.tsx` 队列卡片消费 `it.progress`，展示真实进度条；当条目为 `failed` 时，点击或悬浮可查看后端返回的真实报错原因 `it.error`。
* **FR-303 (真实错误透传)**：前端全面废除“智能剪辑失败，请确保后端服务正常运行”等硬编码文字，统一向用户透传 `err?.response?.data?.detail`。

## 4. 验收标准与边界测试矩阵

| 场景 | 输入操作 | 预期输出与系统行为 | 验证方式 |
| :--- | :--- | :--- | :--- |
| **幽灵消除** | 压制成片后，在素材库删除口播素材并重启后端服务 | 数据库中工程记录被删除；`storage/tasks/<task_dir>/` 被删除；重启后该工程绝不复活 | 自动化端到端测试 |
| **并发竞态** | 素材 A 正在 ASR 识别时，快速切换到素材 B | 素材 A 的 Promise 被 Abort；素材 B 页面不被素材 A 的返回污染 | UI 模拟竞态测试 |
| **ASR重试** | 模拟网络返回一次 502 Bad Gateway 然后恢复 200 | ASRRunner 自动退避重试并在第 2 次成功，不中断剪辑流 | 单测 Mock 测试 |
| **批量取消** | 提交 5 个视频批处理后立即点击“取消批次” | 后端任务立即停止，状态变更为 `canceled`，未执行项停止压制 | 批处理测试 |
| **进度联动** | 点击“智能初剪与纠偏” | 界面呈现阶梯式进度条变化（15%->45%->70%->90%->100%），文本实时同步 | 交互验证 |
