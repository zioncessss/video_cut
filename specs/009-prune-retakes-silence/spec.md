# Feature Specification: 智能剔除口播视频头尾动作与口误重说 (prune-retakes-silence)

**Feature Branch**: `009-prune-retakes-silence`

**Created**: 2026-09-20

**Status**: Draft

**Input**: User description: "问题明确：因为输入是手机录制的口播视频，所以视频里面包含一些刚开始和结束的录制开始和录制结束动作，还有可能因为口误重说词或话；这些内容需要删除；方案可能是进行区分该删除的位置，先用语音字幕判断，开始和结束中间沉默期久，删除掉，然后看到重复的词，中间稍作停顿又说的一个判断，那就舍弃前面说的用后面说的；"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手机口播录制头尾动作与静音自动剔除 (Priority: P1)

作为视频创作者，当我录制口播视频并导入系统后，视频最前端通常有数秒准备动作（例如找镜头、摆正坐姿、深呼吸、看提词器）直至开口说话，末尾通常有说完停顿并伸手去点击手机屏幕结束录制的废动作。系统能通过语音字幕时间轴，自动检测出第一句有效人声前与最后一句有效人声后的无效区间，并将其标记为剔除片段，使成片从主播发声瞬间干脆利落地开始，在主播语毕瞬间利落地结束。

**Why this priority**: 这是所有手机录制口播毛片中最稳定出现、最消耗初级剪辑工时的废片部分，直接决定粗剪后成片的专业质感与基础紧凑度。

**Independent Test**: 导入一段包含前置 4 秒无声动作和后置 3 秒关机动作的口播原始视频，系统自动识别出首尾冗余区间；在工作台播放预览与导出时，前置 4 秒与后置 3 秒被无缝跳过，直接从第一句发音开始至最后一句语毕收尾。

**Acceptance Scenarios**:

1. **Given** 导入一段口播视频，前 3.5 秒为主播调整姿势的静音/轻微环境音，随后开始第一句发言“今天我们来拆解倒车入库”，**When** 系统完成语音识别并执行粗剪分析，**Then** 系统自动将 0.0s 至第一句发音起始（保留设定的微量安全气口缓冲）区间标记为“头端剔除”；
2. **Given** 视频末尾在主播说完整段口播最后一句后，间隔 2.8 秒主播才伸手关闭手机录制，**When** 系统分析完毕，**Then** 系统自动将最后一句发音结束（保留微量安全气口缓冲）至视频总时长的区间标记为“尾端剔除”；
3. **Given** 用户在工作台播放视频，**When** 播放器播放到带有剔除标记的区间，**Then** 播放指针自动跳过该区间，无缝衔接至下一段有效发言。

### User Story 2 - 口误重说与卡壳智能识别与“留后弃前”剔除 (Priority: P1)

作为口播录制者，录制过程中由于忘词或读错字，常常会在停顿一下之后，重新把刚才那句话或那个词完整讲一遍（例如：“先将车身...（停顿 1.5 秒）...先将车身对齐右侧黄线”）。系统通过比对相邻语音片段的文本词汇重叠度与停顿间隔，自动识别出口误重说现象，遵循“舍弃前面说的，保留后面说的”原则，把前一次未说完或说错的废句标记为剔除，保留后一次正确完整的表述。

**Why this priority**: 口误重说是口播毛片处理中最繁琐的痛点，人工反复听辨并手动切除费时费力；智能识别并“留后弃前”是实现真正自动化粗剪的核心价值。

**Independent Test**: 导入一段包含典型口误重说的口播素材（说话人卡壳后停顿 1 秒重新说），系统能够精准定位重说前后的时间边界，并将前一次口误片段置为剔除状态，预览听感连贯完整。

**Acceptance Scenarios**:

1. **Given** 主播在发言中出现重复词句且中间有明显停顿（如：“我们在科目二...（停顿 1.2 秒）...我们在科目二考试的时候一定要注意”），**When** 智能分析执行，**Then** 前一个未完成的片段“我们在科目二...”被标记为“口误重说已剔除”，后一个完整句子被完整保留；
2. **Given** 主播连续卡壳了 2 次才说顺第三次（多轮重说），**When** 系统分析，**Then** 系统将前两次尝试均标记为剔除，最终仅保留第三次清晰完整的表达；
3. **Given** 口误片段被剔除后，**When** 用户在剪辑工作台回放音频，**Then** 声画过渡平滑，没有明显的音爆或突兀的吞字感。

### User Story 3 - 粗剪结果可视化审阅与可逆微调 (Priority: P2)

作为创作者，我希望在剪辑工作台中清楚地看到哪些片段被系统判断为“录制头尾废片”或“口误重说”，并保留最终的控制权：对于偶发的误判（如正常的叠词强调修辞，或故意留白的停顿），我能一键反选恢复；对于切点略微偏紧的情况，我可以手动微调切片起止时间。

**Why this priority**: 遵循系统宪章“可逆与可微调”原则，AI 识别不可能达到 100% 完美，直观的视觉反馈和零负担的微调能力是保障生产可用性的安全兜底。

**Independent Test**: 在时间轴与字幕列表中能清晰看到被划线或灰色高亮的“已剔除片段”；点击“恢复”按钮后该片段立刻恢复为有效轨道内容；再次播放时该片段恢复正常发声。

**Acceptance Scenarios**:

1. **Given** 某个片段被系统判定为剔除片段，**When** 用户在字幕列表查看该条目，**Then** 该条目带有明显的“已剔除 (头尾冗余/口误重说)”状态标识与划线视觉呈现；
2. **Given** 用户发现主播讲的“一定要看、一定要看反光镜”是强调修辞而非口误，**When** 用户点击该条目旁的“恢复/保留”切换按钮，**Then** 该片段立即恢复为有效播放状态，时间轴联动同步；
3. **Given** 用户觉得自动剪切点稍微卡得太紧，**When** 用户拖动或输入调整开始/结束时间点，**Then** 系统实时更新该片段有效区间并在播放器中精准对齐。

### User Story 4 - 批量处理与配置偏好持久化 (Priority: P3)

作为需要批量处理多条视频的创作者，我希望在批量剪辑或全局设置中保存我习惯的粗剪偏好（如默认安全气口缓冲时长、是否自动执行口误剔除、停顿敏感度），使批量产出的视频均能自动执行高质量标准化粗剪。

**Why this priority**: 批量生产是口播短视频矩阵账号的核心场景，配置持久化可以消除重复的手动微调工作。

**Independent Test**: 在设置中配置“头尾保留气口 0.3 秒，自动剔除口误重说”，导入多条素材进行批量粗剪时，所有输出工程均按此偏好统一自动应用。

**Acceptance Scenarios**:

1. **Given** 用户在设置页调整“头尾动作剔除”与“口误重说过滤”的默认配置，**When** 用户保存设置，**Then** 配置持久化生效，后续新建项目默认继承该配置；
2. **Given** 用户在批量处理页添加 5 个口播素材，**When** 启动批量粗剪，**Then** 5 个任务均自动应用头尾动作裁剪和口误重说剔除，生成干净紧凑的草稿。

### Edge Cases

- **伴随杂音但无人声的头尾动作**：录制开始或结束时手机麦克风可能录入按键摩擦声、衣服摩擦声或深呼吸声。系统必须基于可靠语音检测（ASR 真实文本起始与有声区间）判定有效人声起点，而不是将高分贝摩擦声误当成口播内容。
- **排比与修辞强调性重复**：主播连续快速重复词语以增强语气（如“注意！注意！注意这一点！”），其语流连续、停顿极短且语调递进。系统需根据停顿时间（如短于口误停顿阈值）与句式完整性进行区分，避免将其误判为口误。
- **长时间中途思考停顿但无重说**：主播在中途看了 2 秒提词器后继续说全新的下一句。此场景不属于口误重说，系统不得将其误标记为口误，而应按照中段单纯停顿的策略进行处理。
- **连续多次卡壳（三连重说）**：主播同一句话卡壳说了三次才顺畅（尝试1 → 停顿 → 尝试2 → 停顿 → 尝试3）。系统必须能够向前追溯所有关联的未完成重合片段，将前两次尝试全部标记为剔除，仅保留最后一次。
- **全篇无有效发音或极度含糊素材**：视频全程无人声或全是嘈杂环境音，ASR 未识别出有效字幕。系统必须保底完整保留原视频，严禁生成时长为 0 的异常工程或切片。
- **剪切点前后字词吞字与爆音**：若直接在发音波形零点或首字边缘硬切，极易出现吞字（如将“我们”切成“们”）或轻微爆音（Click/Pop 音）。系统必须在识别出的时间戳外侧预留平滑过渡保护缓冲（Padding）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须能够自动分析口播视频的语音识别时间轴，精确定位视频第一句有效语音的发声起点与最后一句有效语音的收音终点。
- **FR-002**: 系统必须支持将视频起始位置至第一句有效发声起点之间的冗余区间（包括准备动作与初始无声期）自动标记为剔除片段。
- **FR-003**: 系统必须支持将视频最后一句有效收音终点至视频结束之间的冗余区间（包括结束动作与尾部静音期）自动标记为剔除片段。
- **FR-004**: 系统在剔除头尾区间时，必须在有效发音的外侧保留可配置的安全气口缓冲时长（Padding，默认建议 0.2 秒），严禁截断开头发音首字或末尾余音。
- **FR-005**: 系统必须能够检测语音文本中的相邻重复字词、短语或句子重叠模式，并结合片段间的停顿时间判定口误重说事件。
- **FR-006**: 针对判定成立的口误重说事件，系统必须遵循“留后弃前”规则，将前一段口误/未说完片段标记为剔除，完整保留后一段修正复述。
- **FR-007**: 针对多次连续卡壳重说（连续 2 次及以上重说同一内容），系统必须能关联并将所有前置尝试片段一次性标记为剔除，仅保留最终成功表述。
- **FR-008**: 系统必须通过停顿间隔阈值与断句特征区分口误重说与正常语言修辞（如连续强调、连读叠词），避免误杀正常强调表达。
- **FR-009**: 系统必须在剪辑工作台界面直观展示剔除决策，对被标记为剔除的片段提供清晰的视觉区分（如灰色划线、独立标签或折叠展示），且必须保证非破坏性（允许用户一键切换保留/剔除状态）。
- **FR-010**: 系统必须允许用户在界面直观拖动微调或输入数值调整剔除片段的起止时间点。
- **FR-011**: 系统在时间轴播放与最终成片导出合成时，必须自动跳过所有处于“剔除”状态的时间区间，无缝拼接保留片段。
- **FR-012**: 系统必须在自动剪辑流水线（Auto Edit Pipeline）的 ASR 语音识别之后、语义空镜匹配之前，自动执行全套粗剪分析；默认将识别出的头尾动作废片、口误重说前驱尝试以及中段单纯长停顿（静音超过 1.2 秒的空白气口压缩）自动置为“已剔除”状态，时间轴与播放器默认无缝跳过，同时保留完整可逆微调能力。
- **FR-013**: 系统必须在底层存储中持久化每个切片条目的剔除状态（保留/剔除）及剔除原因（头尾冗余/口误重说/中段长停顿/手动剔除），且不得破坏权威数据库中原始 ASR 记录。

### Key Entities *(include if feature involves data)*

- **SpeechPruneSegment (剪辑切片/区间条目)**:
  - `segment_id`: 切片唯一标识。
  - `start_time`: 起始时间（秒）。
  - `end_time`: 结束时间（秒）。
  - `text`: 对应字幕文本内容。
  - `prune_status`: 剔除状态（`keep` 保留 / `pruned` 剔除）。
  - `prune_reason`: 剔除原因（`none` / `head_idle` 头部动作 / `tail_idle` 尾部动作 / `retake_discard` 口误重说 / `mid_silence` 中段长空白 / `user_manual` 用户手动）。
  - `confidence`: 算法判定置信度。
  - `retake_target_id`: 若为口误重说剔除，指向其替代保留的目标切片 ID。
- **PruneConfig (粗剪与重说过滤配置)**:
  - `enable_head_prune`: 是否启用头部冗余自动裁剪（默认开启，True）。
  - `enable_tail_prune`: 是否启用尾部冗余自动裁剪（默认开启，True）。
  - `enable_retake_prune`: 是否启用口误重说自动剔除（默认开启，True）。
  - `enable_mid_silence_prune`: 是否启用中段单纯长停顿自动压缩（默认开启，True）。
  - `mid_silence_threshold`: 中段无声空白压缩阈值（秒，默认 1.2s，超出部分压缩并保留 0.3s 气口）。
  - `padding_duration`: 发音起止外侧安全气口缓冲时长（秒，默认 0.25s，防吞字）。
  - `retake_pause_min`: 判定口误重说的最小停顿间隔（秒，默认 0.5s）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 手机录制口播视频的头尾录制动作（开始准备动作与结束按键动作）自动剔除识别准确率达到 95% 以上，且无首字或尾字音节截断。
- **SC-002**: 典型口误卡壳重说片段（伴随停顿的重复复述）的自动识别召回率达到 85% 以上，并将前置口误废句 100% 正确标记为弃用。
- **SC-003**: 正常修辞强调（如快速无停顿连说“看这里看这里”）的误杀率低于 5%。
- **SC-004**: 用户在剪辑工作台完成一段 3 分钟口播毛片的基础粗剪（去掉头尾动作与重说口误）的操作时间由原本人工查找修剪的平均 5 分钟降低至 30 秒以内（即：AI 自动标记完成，用户仅需扫视确认）。
- **SC-005**: 粗剪跳过处理后的视频在播放与导出合成时声画同步，切口处无卡音、断句爆音或画面抽帧。

## Assumptions

- 口播视频输入具有相对清晰的主体人声音频，系统已具备基础的 ASR 语音识别与时间戳对齐能力。
- 手机拍摄的口播视频绝大多数遵循“按开始键 -> 准备 -> 说话 -> 说完 -> 伸手按停止键”的物理行为习惯。
- 口误重说通常伴随“说话中断/卡壳 -> 停顿（吸气、懊恼或思考） -> 重新从句首或词首再讲一遍”的行为特征，重讲时说话人语速或发音恢复正常。
- 用户希望保留对成片内容绝对的掌控权，因此系统在进行智能剔除时应采用非破坏性标记，随时允许创作者一键撤销或二次微调。
- 视频切除片段后，时间轴将自动闭合（Ripple Cut 效果），使留存的有效片段紧密顺畅相接。
