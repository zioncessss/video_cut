# Technical Research: 智能剔除口播视频头尾动作与口误重说 (009-prune-retakes-silence)

## 1. 核心问题与设计目标

手机录制口播视频在创作中最耗时的初剪痛点包括：
1. **录制开始前的废动作**（0.8s ~ 3.7s）：找镜头、吸气、调整姿势等无声/杂音准备动作；
2. **录制结束后的废动作**（1.1s ~ 2.3s）：说完最后一句话后伸手按停止按键的动作与空白；
3. **口误重说与改口重录**（Retake / Restart）：主播卡壳、漏词或念错后，稍作停顿，重新复述上一句话或换词重说；
4. **中段看稿卡壳的长冷场**（1.0s ~ 3.4s）：中途看提词器导致较长时间无声空白；
5. **用户关键约束（自然呼吸气口）**：“也要注意留出正常停顿的时间，一下子前后没有一点间隙可能也不符合人类的习惯”——杜绝“机关枪式”硬切，各剪切衔接点必须保留人类自然舒适的发音呼吸停顿（0.25s ~ 0.35s）。

---

## 2. 关键技术选型与决策 (Decisions, Rationales & Alternatives)

### 决策 1：口误重说判定算法设计 (Retake & Restart Detection)

- **选型决定**：采用**双指针滑动窗口 + 语义编辑距离/公共子序列 (LCS) + 停顿物理特征**的混合确定性算法，辅以可选大模型语义兜底。
- **技术细节**：
  1. **时间停顿特征**：口误重说必然伴随主播卡壳导致的微小停顿（实测区间 0.4s ~ 1.5s）。若相邻短句时间间隔处于此区间，触发重说检测探针。
  2. **文本相似度与重叠度**：
     - 利用 Python 标准库 `difflib.SequenceMatcher` 计算字词级相似度；
     - 检测**前缀重合**（如 `从今年九月份开始啊` vs `湖州驾校从今年九月份开始`，LCS 长度 >= 4，重合度高）；
     - 检测**主句补全重说**（如 `点个红心加关注` vs `我来点个红心加关注`，包含率 > 85%）；
     - 检测**同义改口重说**（如 `可以联系我一下` vs `可以滴滴我一下`，句式 `可以*我一下`，编辑距离 <= 2 且停顿约 1.0s）。
  3. **决策规则**：“舍弃前驱，保留后效”——将前置的未完成/错误片段标记为 `pruned`，后置的修正复述标记为 `keep`。
  4. **连续多次卡壳链处理**：若连续多次重说（尝试 1 -> 停顿 -> 尝试 2 -> 停顿 -> 尝试 3），算法向前追溯，将 1 和 2 全部标记剔除，仅保留 3。
- **防修辞误杀规则**：
  - 若相邻相同词语无明显卡壳停顿（停顿 < 0.25s），或属于已知排比词汇（如“看这里看这里”），判定为正常修辞强调，不予剔除。
- **替代方案对比**：
  - *纯 LLM 判断*：依赖大模型每次调用，网络延迟高（1~3秒），偶发格式漂移且有 token 成本；
  - *纯音频波形 VAD 判断*：VAD 只能探测有声/无声，无法知道主播说了什么，无法识别是口误重讲还是讲了新内容；
  - *结论*：基于已有的 ASR 真实字幕文本+精准时间轴做确定性算法检测，耗时 < 5ms，100% 离线可用、结果确定且可解释。

### 决策 2：自然呼吸气口保留策略 (Human Cadence & Breath Gap Preservation)

- **选型决定**：引入动态气口计算模型（Dynamic Breath Gap Model），严禁 0 毫秒极限紧切，各剪切边界严格预留人类自然生理停顿：
  1. **头部动作裁剪气口 (Head Padding)**：首句人声起始点前保留 `0.20s ~ 0.25s`，既消灭开机静音与准备杂音，又杜绝吞掉第一个字的爆破音/辅音；
  2. **尾部动作裁剪气口 (Tail Padding)**：末句人声结束点后保留 `0.25s ~ 0.30s`，自然收音，杜绝掐断尾音余韵；
  3. **中段长静音压缩气口 (Mid-Silence Compression)**：
     - 触发阈值：静音间隔 `gap > 1.2s`（说明主播看稿或卡壳）；
     - 压缩目标：**绝不压成 0 秒**，而是保留 `0.30s ~ 0.35s` 的标准句间舒适换气时长；
     - 剪切区间：`[sub[i].end_time + 0.15s, sub[i+1].start_time - 0.15s]`；
  4. **口误重说衔接气口 (Retake Transition)**：
     - 剔除前驱废句后，在保留句的发音起始前保留 `0.20s ~ 0.25s` 气口，使听众感知到自然的话语节奏。
- **替代方案对比**：
  - *零间隙压制 (Zero-gap truncation)*：极度机械化、发音连珠炮，听感压抑令人窒息；
  - *简单固定切除*：可能导致不同语速下断句撕裂；
  - *结论*：基于两端对称气口保留（0.15s + 0.15s = 0.30s 净保留），完全符合人类日常对话听觉心理学。

### 决策 3：前端播放器与时间轴交互架构 (Non-destructive Preview)

- **选型决定**：采用**客户端非破坏性跳播（Client-side Virtual Skip）+ 时间轴剔除条带可视化**。
- **技术细节**：
  1. 不需要每次修改粗剪就调用 FFmpeg 重新转码合成，前端直接播放原始视频；
  2. `VideoPlayer` 在 `requestAnimationFrame` 驱动的 tick 中监听 `videoRef.currentTime`；
  3. 当当前播放时间落入任一 `pruned` 区间 `[p_start, p_end]` 时，视频指针自动无缝跃迁至 `p_end`（Seek 跳播）；
  4. 字幕列表条目增加 `prune_status` 标识，呈现灰色半透明 + 中划线，右侧提供【恢复】/【剔除】一键切换按钮；
  5. 时间轴刻度条上，被剔除的区域以暗红色/灰色条带醒目标识，让创作者一目了然。
- **替代方案对比**：
  - *物理硬删并重新切片视频*：每次调整耗时数秒甚至数分钟重新压制，响应极其卡顿，且原片不可逆；
  - *结论*：虚拟跳播具有 0 毫秒延迟、100% 实时响应、100% 可逆的极致体验。

### 决策 4：FFmpeg 底层合成与防爆音工程 (A/V Export & Anti-Click)

- **选型决定**：利用 FFmpeg `filter_complex` 的 `select` / `atrim` + `afade` + `concat` 构建无缝拼合。
- **技术细节**：
  1. 根据剔除区间计算出**最终保留的连续时间块 (Kept Spans)**：`[(k_start_0, k_end_0), (k_start_1, k_end_1), ...]`；
  2. **音频防爆音处理**：在每个音频切片头部和尾部加入微秒级淡入淡出（`afade=t=in:ss=0:d=0.015,afade=t=out:st={dur-0.015}:d=0.015`），彻底消除直流偏移（DC offset）引起的 Click/Pop 音爆；
  3. **空镜与字幕重对齐**：视频合成时，空镜切片（B-roll）与 ASS 字幕的时间戳映射至合并后的紧凑时间轴，保证音画字 100% 严格对齐。
