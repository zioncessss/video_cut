# Feature Specification: 字幕实时保存与成片预览所见即所得同步 (007-subtitle-sync-preview)

**Feature Branch**: `007-subtitle-sync-preview`

**Created**: 2026-09-19

**Status**: Draft

**Input**: User description: "我这边改了字幕，但是好像没有实时保存下来，生成预览没有按照我设置的改变，然后生成预览的字体大小和实时编辑的还是不不同步得"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 字幕即时持久化与编辑状态明确反馈 (Priority: P1)

用户在剪辑工作台的字幕时间轴列表中编辑任何一句字幕文本或增删高亮词时，系统能够即时响应，界面提供清晰明确的保存状态提示（如“保存中...”、已保存“✓ 已同步”）。当用户失焦（Blur）、按回车确认或触发渲染时，立即将最新修改提交至持久化存储，彻底消除数据丢失隐患与心理不确定感。

**Why this priority**: 字幕是短视频内容的核心载体。用户对字幕的微调和错别字修正属于高频强交互操作，任何保存延迟、静默丢数据或不确定感都会严重破坏用户对系统的信任。

**Independent Test**: 在字幕列表修改某句文本，观察界面即时呈现保存状态指示；失焦或等待防抖完成后刷新页面，验证修改内容 100% 完整保留。

**Acceptance Scenarios**:

1. **Given** 用户在工作台选中某条字幕并输入新文本，**When** 用户正在键入，**Then** 界面即时呈现“正在保存...”或未存脏标记状态，且状态更新采用不可变对象拷贝，不破坏 React 响应性。
2. **Given** 用户完成文本输入，**When** 触发输入框失焦（Blur）、敲击 Enter 确认或防抖计时器到达，**Then** 系统立即向后端发起保存请求，成功后状态更新为“✓ 已保存”并记录真实修改时间。
3. **Given** 处于弱网或后端短暂不可用时，**When** 保存失败，**Then** 界面保留用户输入的内容，并在该字幕卡片显著标注“保存失败，点击重试”，严禁清空或重置为旧内容。

---

### User Story 2 - 生成预览前强制刷新最新字幕与样式并破除成片缓存 (Priority: P1)

当用户点击“生成预览”或“渲染合成”时，系统自动取消所有等待中的防抖计时器，强制将当前最新的字幕列表和视觉策略同步至后端数据库并确认落盘；随后再启动高质量视频复合渲染。渲染完成后，播放器以唯一防缓存机制（Cache-Busting）刷新视频流，确保用户在成片播放器中看到的画面与文字完全符合最新设定。

**Why this priority**: 用户在修改完字幕后最直接的诉求就是“立刻看成片效果”。如果点击生成预览后因为防抖未完或浏览器缓存而展示旧成片，用户会误以为修改失效。

**Independent Test**: 修改字幕内容后立即点击“生成预览”，断言合成任务携带最新的字幕文本启动，合成后成片播放器即时刷新且所呈现的画面字幕与输入完全一致。

**Acceptance Scenarios**:

1. **Given** 用户刚刚修改完字幕或排版策略尚未经过防抖延时，**When** 用户点击“生成预览/渲染合成”，**Then** 系统自动阻塞并同步提交最新字幕与策略数据，待后端落库确认后再执行复合渲染流程。
2. **Given** 视频渲染合成成功完成，**When** 前端切换至“成片预览”模式，**Then** 视频播放器自动附带纳秒级防缓存参数重新装载新成片，杜绝因同名或浏览器磁盘缓存导致的旧画面回放。
3. **Given** 用户当前停留在“已压制成片”模式，**When** 用户在右侧修改了任何字幕文本或策略，**Then** 界面友好提示“当前播放的是上一版成片，需重新生成预览”，并提供一键快捷重新生成入口，或者自动切回实时交互预览模式呈现即时效果。

### User Story 3 - 交互编辑器与导出成片字号及排版像素级所见即所得 (WYSIWYG) 对齐 (Priority: P2)

在实时交互编辑器的播放器中，字幕、横幅和水印的虚拟 DOM 叠加层与实际视频画面的物理渲染尺寸精准等比对齐（排除播放器外围黑边与视口伸缩形变干扰）。实时预览中所见到的字体大小、行间距、边距及单行折行换行点，与 FFmpeg ASS 压制成片呈现的像素视觉效果保持 1:1 绝对一致。

**Why this priority**: 视频创作者非常依赖实时编辑时的视觉直觉。如果预览时单行不折行、字号适中，合成后却因为字号计算基准不同而发生折行或字号过大/过小，将导致反复无效试错。

**Independent Test**: 在编辑器中将字幕字号调整为小号（56px）、中号（72px）或大号（86px），截取实时预览帧与压制成片相同时间点的视频帧进行重叠比对，验证字号在视频幅面中的相对占比与折行位置一致无偏差。

**Acceptance Scenarios**:

1. **Given** 视频播放器由于容器宽高限制出现左右或上下黑边（Letterbox / Pillarbox），**When** 计算字幕、横幅与水印的缩放因子时，**Then** 系统依据视频实际画面的物理显示像素（排除黑边）进行动态比例换算，严禁使用外围黑底容器宽度作为缩放基准。
2. **Given** 用户调节字幕字号（如 72px 对应 1080x1920 竖屏画布的 3.75% 画面高度），**When** 在实时编辑模式下渲染，**Then** 虚拟字幕的 CSS 像素尺寸严格按 `视频实际像素高度 / 1920 * chosen_font_size` 进行换算，与 libass 渲染引擎逻辑完全对称。
3. **Given** 用户自定义字幕最大宽度百分比（如 90%），**When** 在预览与成片中渲染，**Then** 预览容器宽度百分比严格对齐实际视频画面宽度的 90%，ASS 边距（margin_h）严格等比生成，确保折行时机 100% 相同。

### Edge Cases

- **超快连续输入后立即点击生成**：用户正在输入最后一个字符的同时点击了“生成预览”，系统通过引用捕获或即时 commit 确保该字符被完整保存并渲染进成片。
- **窗口尺寸缩放与全屏切换**：用户拖拽缩放浏览器窗口时，`ResizeObserver` 即时重新测量实际视频像素矩形，字幕与手柄随之无缝等比缩放，不发生位移错位。
- **16:9 横屏与 9:16 竖屏切换**：在横竖屏画幅切换时，字号基准与安全边距平滑自适应，保持在画面中的合理阅读占比。
- **并发保存竞态冲突**：用户输入触发的防抖保存与失焦保存、生成前强制保存之间设置互斥锁或序列化处理，避免旧请求覆盖新数据。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 字幕列表必须提供实时的保存状态可视化反馈，包括但不限于“编辑中”、“保存中”与“已同步”状态标识；
- **FR-002**: 字幕文本框在失焦（`onBlur`）或回车提交时，必须立即将修改内容提交持久化，不得纯被动依赖延时防抖；
- **FR-003**: 前端状态管理更新字幕列表时必须使用不可变数据结构（Deep/Object clone），严禁对原对象进行浅层属性原地修改，防止 React 组件跳过刷新；
- **FR-004**: 点击“生成预览/渲染合成”时，系统必须首先执行前置保存刷新，同步提交未保存的字幕列表与排版策略，并在收到持久化确认后再触发渲染接口；
- **FR-005**: 复合渲染接口调用成功后，前端视频播放器必须附加唯一时间戳参数重载成片视频地址，彻底规避浏览器本地缓存导致的陈旧视频帧回放；
- **FR-006**: 在成片播放模式下，若检测到字幕或策略已被修改，界面必须提供显式状态指引（如“内容已更改，点击重新生成”），避免用户误判修改未生效；
- **FR-007**: 视频播放器的字幕、横幅与水印叠加层必须以实际视频画面的有效视口（Active Video Frame Viewport）为定位与缩放父容器，严禁将包含 Letterbox/Pillarbox 黑边的外层容器作为坐标与尺寸基准；
- **FR-008**: 实时预览字幕字号与 FFmpeg ASS 压制字号必须使用统一度量公式：`PreviewPx = Math.round(BaseSize * (ActualVideoHeight / 1920))`，实现跨渲染引擎的像素级等比映射；
- **FR-009**: 字幕区域最大可用宽度在实时预览中必须以实际视频画面宽度为 100% 基准计算，使 CSS 自动折行行为与 libass 的 `MarginL/MarginR` 换行行为严格保持一致；
- **FR-010**: 字幕、横幅、水印的 2D 拖拽位置坐标（X/Y 百分比）必须基于实际视频有效画面区域计算，拖拽手柄与边界限制不得超出实际视频画面边界；
- **FR-011**: 后端 `PUT /projects/{id}/subtitles` 接口落库时必须确保 SQLite 事务提交成功后再返回 200，并保留 `is_manual_edited` 手动标记；
- **FR-012**: 当后端持久化或渲染接口返回失败时，前端必须捕获异常并保留当前编辑态，给出清晰的中文错误原因提示。

### Key Entities

- **VideoViewportMetrics**: 播放器内部实际视频画面物理呈现像素矩形（`videoLeft`, `videoTop`, `videoWidth`, `videoHeight`），排除黑边。
- **SaveStatus**: 字幕与策略的持久化状态枚举，包括 `IDLE`（空闲）、`DIRTY`（待存）、`SAVING`（保存中）、`SAVED`（已存）、`ERROR`（失败）。
- **SubtitleSegment**: 增强后的字幕实体，包含文本、时间戳、高亮词表、分镜决策与手动修改标记。
- **EditingStrategy**: 统一视觉策略模型，包含主题、字号、位置与开关参数。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在字幕列表中完成文本编辑后，修改内容在 500ms 内（或失焦时 0ms 延迟）被可靠持久化，保存状态指示正确率 100%；
- **SC-002**: 点击“生成预览”后生成的成片视频，字幕内容与点击瞬间的最新字幕内容一致率达到 100%，无丢失或滞后现象；
- **SC-003**: 实时交互预览模式下的字幕字高与压制成片中的字幕字高相对误差控制在 **±2% 以内**，单行断行/换行点保持 100% 一致；
- **SC-004**: 渲染成功后成片刷新速度无感知，消除任何因浏览器视频缓存导致的旧画面停留现象。

## Assumptions

- 用户在现代主流桌面浏览器（Chrome/Edge/Electron）中使用系统，支持 `ResizeObserver` 与 CSS 标准属性；
- 原始视频主画幅以 9:16（1080x1920）竖屏为主，同时兼容 16:9 横屏；
- 后端 SQLite 具备毫秒级事务写入能力，短时间内连续单次保存不造成性能瓶颈。
