# Feature Specification: 智能剪辑与自动分镜流水线（Smart Edit & Auto Storyboard Pipeline）

**Feature Branch**: `005-auto-edit-pipeline`

**Created**: 2026-09-17

**Status**: Draft

**Input**: 用户口述需求（智能初剪辑改名、单步纠错移除、AI 判定高亮词替代纯词库、四类分镜自动剪辑规划、转场 AI 决策、批量剪辑与单视频人工修正工作台、封面接口预留）

---

## User Scenarios & Testing

### User Story 1 — 界面动作收敛：智能剪辑一键直达 (Priority: P1)

用户在剪辑工作台看到的主动作按钮统一命名为「智能剪辑」：
- 未生成工程时按钮文案为「智能剪辑」（不再出现「智能初剪辑」「一键智能初剪与纠偏」等旧称）。
- 已有工程缓存时按钮文案仍为「智能剪辑」（不带「重新」前缀），点击后重新执行全流程（音频→ASR→AI 纠偏→高亮→分镜决策）。
- 原「单步纠错」独立按钮从工具栏删除；纠偏能力仍保留在「智能剪辑」全流程与字幕单句编辑中，不丢失功能。

**Why this priority**: 按钮命名与布局是用户每天接触的第一触点，改动小、独立可交付。

**Independent Test**: 打开剪辑页，检查工具栏按钮文案与数量。

**Acceptance Scenarios**:

1. **Given** 已选择口播视频但无工程缓存，**When** 查看工具栏，**Then** 只有一个主动作按钮「智能剪辑」，无「单步纠错」按钮。
2. **Given** 工程已就绪（N 句字幕），**When** 查看工具栏，**Then** 主动作按钮文案为「智能剪辑」，点击后重跑全流程并刷新字幕。
3. **Given** 任意状态，**When** 触发「智能剪辑」失败，**Then** 界面展示真实错误详情，不出现假装成功。

### User Story 2 — AI 判定高亮词 + 预设高亮词库双引擎 (Priority: P1)

字幕高亮词由两个来源合成，且全部可在界面上查看与调整：
1. **预设高亮词库**（storage/glossary.json `keywords`：location/venue/experience/lesson/emphasis）：确定性命中，零延迟，作为兜底；
2. **AI 判定**：AI 纠偏时对每句输出 1~2 个高亮重点词（优先地点、时间、数字、核心卖点），与词库命中词合并去重。

已实测验证（2026-09-17，glm-5.3-flash 直连，12 句 17.8s）：AI 能稳定、合理地判定「九月份」「湖州驾校」「五万平」「一把过」等地域/时间/卖点重点词。

**Why this priority**: 高亮是成片卖相的核心，且 AI 判定链路已存在（`highlight_keywords`），补齐词库兜底语义与时间轴可视化即可闭环。

**Independent Test**: 对含地点/时间/卖点的口播执行智能剪辑，检查每句高亮词来源合并结果。

**Acceptance Scenarios**:

1. **Given** 词库 emphasis 含「一把过」，**When** 某句文本含「一把过」，**Then** 该句高亮词包含「一把过」（词库命中，无需 AI）。
2. **Given** AI 返回某句 `highlight_keywords: ["九月份","湖州驾校"]`，**When** 词库未收录「九月份」，**Then** 该句高亮词仍包含「九月份」（AI 判定生效）。
3. **Given** AI 调用失败或超时，**When** 全流程降级为词库确定性纠偏，**Then** 词库命中的高亮词仍在，界面如实提示降级引擎。
4. **Given** 任意字幕句，**When** 用户在时间轴上手动增删高亮词，**Then** 修改立即持久化到工程并影响后续渲染。

### User Story 3 — 高亮词在字幕时间轴轨道上可视化与可调整 (Priority: P1)

在「字幕与时间轴轨道」列表中，每句字幕直接以可交互标签形式展示其高亮词（区分来源徽标：词库/AI/手动）；点击标签可删除该高亮词，输入框可添加新词；高亮词随字幕句编辑联动刷新。

**Why this priority**: 用户明确提出「在字幕时间轨道上也能显示调整高亮词就更好」，且它是 Story 2 的验收界面。

**Independent Test**: 打开字幕列表，任一句可见高亮词标签并可增删。

**Acceptance Scenarios**:

1. **Given** 工程有 13 句字幕，**When** 展开字幕时间轴列表，**Then** 每句下方展示高亮词标签及来源徽标。
2. **Given** 某句高亮词「过来学」不符合预期，**When** 点击标签 × 删除，**Then** 渲染成片中该词不再高亮。
3. **Given** 用户为某句添加新词「大改革」，**When** 保存并渲染，**Then** 该词在成片中按当前主题色高亮放大。

### User Story 4 — 四类分镜素材体系与「体验空镜」定名 (Priority: P1)

素材库由四类分镜构成，界面上「体检空镜」更名为「体验空镜」（internal key 由 `medical` 迁移为 `experience`）：

| 分镜 | key | 触发语义 | 定位说明 |
|---|---|---|---|
| 口播分镜 | talking_head | 主视频，用户上传 | 剪辑主体：AI 解析其文本，匹配下列空镜分镜 |
| 场地空镜 | venue | 提及地点/场地：湖州驾校、萧山学车、杭州学车、训练场、五万平、考场 | 环境展示：校区/训练场/考场画面 |
| 体验空镜 | experience | 提及用户体验流程：体检、拍照、面签、报名、拿证、上车初体验 | 学员视角流程画面（原「体检空镜」扩展升级；客户语义未最终确定前，按「用户体验全流程」归类，词库可随时调整触发词） |
| 教学学车空镜 | lesson | 提及教学/练车场景：教练、科目二、倒库、侧方、离合 | 教学动作画面 |

**Why this priority**: 分类体系是分镜决策、素材上传与批量剪辑的共同地基；`medical` 键名迁移必须在数据量小时完成。

**Independent Test**: 上传素材到四类分类；对含「体检」文本的工程验证其匹配到 experience 类素材。

**Acceptance Scenarios**:

1. **Given** 素材库页面，**When** 查看分类标签，**Then** 四类显示为：口播分镜/场地空镜/体验空镜/教学学车空镜。
2. **Given** 历史工程中存在 `matched_category="medical"` 的字幕，**When** 迁移后加载工程，**Then** 自动映射为 `experience` 且空镜引用不失效。
3. **Given** glossary.json 中 `keywords.medical` 旧键，**When** 迁移脚本执行，**Then** 词库键更名为 `experience` 并自动备份原文件。

### User Story 5 — AI 分镜决策：切哪里、切多久、怎么转场 (Priority: P1)

「智能剪辑」全流程新增第三步 AI 决策：AI 阅读纠偏后的字幕（id+文本+起止时间），输出结构化分镜决策：
- 每句是否切空镜、切哪类（venue/experience/lesson）；
- 空镜播放时长（≤该句时长，初版约束 60%~100%）；
- 转场时长（0.3~0.5s，AI 可按语境决策，也可整体沿用默认值）；
- 决策理由（一句话，供界面展示与人工复核）。

约束：纯情绪/行动号召句（如「点红心关注」）不切空镜；口播音轨与字幕始终来自原口播视频，转场仅画面切换（ concat 硬切或 xfade 叠化，音频轨不动）；空镜素材初版按分类随机选取。

已实测验证：glm-5.3-flash 对 12 句样本可输出合规 JSON 决策（codex 代理 112s 成功；直连 60s 超时，需放宽超时/流式，见 research.md）。

**Why this priority**: 这是「自动剪辑」从关键词规则升级为 AI 决策的核心跃迁。

**Independent Test**: 用固定样本字幕调用决策接口，校验 JSON 结构、边界约束与幂等重跑。

**Acceptance Scenarios**:

1. **Given** 含「自建五万平训练场」的字幕句，**When** AI 决策，**Then** 该句获得 `venue` 类空镜及合理时长。
2. **Given** 「点红心关注教练」类句子，**When** AI 决策，**Then** 返回 `broll=null` 且不产生空镜区间。
3. **Given** AI 决策完成，**When** 查看时间轴，**Then** 空镜区间、时长、理由逐句可视化展示，且可手动改分类/换素材/调时长。
4. **Given** AI 决策失败，**Then** 降级为现行关键词匹配规则并如实提示，流程不中断、不假装成功。

### User Story 6 — 批量剪辑与单视频人工修正工作台 (Priority: P2)

用户可一次选择多个口播视频发起批量智能剪辑：每个视频独立走完整流水线（转写→纠偏→高亮→分镜→合成），批量任务展示每个视频的进度与结果；对不满意的视频可点入其单视频剪辑工作台（即现有 VideoEditor 工作台）做人工修正后重新合成。

**Why this priority**: 依赖 Story 1/2/5 的流水线稳定，属于规模化生产力场景；现有单视频管线与 `/progress` 接口已具备，主要补批量编排。

**Independent Test**: 选择 2 个口播视频发起批量剪辑，观察队列进度并点入单视频工作台修正。

**Acceptance Scenarios**:

1. **Given** 3 个口播视频，**When** 发起批量剪辑，**Then** 队列按硬件并发上限执行，每个视频进度独立可见。
2. **Given** 批量结果列表中某视频不满意，**When** 点击进入单视频工作台修改字幕/空镜并重新合成，**Then** 仅该视频重新渲染，批量任务中状态同步更新。
3. **Given** 批量中某视频流水线失败，**Then** 该视频标记失败并展示真实错误，其余视频继续。

### User Story 7 — 标题横幅与水印默认关闭 (Priority: P2)

成片默认不烧录顶部标题横幅与品牌水印（`enable_top_banner=false`、`enable_watermark=false` 作为新工程默认值）；策略工坊保留完整开关与样式能力，待首批成片评审后由用户自行开启。已有工程沿用其已保存的策略值，不被强制改写。

**Why this priority**: 纯默认值调整 + 一处 UI 呈现，改动极小但影响所有新工程。

**Independent Test**: 新建工程查看策略默认值并渲染成片确认无横幅水印。

**Acceptance Scenarios**:

1. **Given** 新建的剪辑工程，**When** 渲染成片，**Then** 画面无标题横幅、无水印。
2. **Given** 用户在策略工坊手动开启水印，**When** 再次渲染，**Then** 水印按配置出现。

### User Story 8 — 视频封面字段与接口预留 (Priority: P3)

工程模型增加封面（cover）字段与生成/设置接口占位：当前版本允许用户从成片中选取任一帧或上传图片作为封面并持久化；AI 封面生成仅做接口预留（未实现的能力显式标注「规划中」，严禁返回假装成功的 Stub）。

**Why this priority**: 后置能力，先固化数据契约避免未来破坏性变更。

**Independent Test**: 为工程设置一张封面图并重新加载工程验证持久化。

**Acceptance Scenarios**:

1. **Given** 已生成成片的工程，**When** 用户点选某帧设为封面，**Then** 封面路径持久化并在工程列表/详情展示。
2. **Given** AI 封面生成入口，**When** 当前版本点击，**Then** 明确提示该能力规划中，不产生伪结果。

## Edge Cases

- **地域约束**：纠偏仅面向浙江地名（湖州/杭州/萧山等）；词库 `location.prompt_hint` 明确「非浙江地名不乱纠」，出现「福州」等一律按词库映射纠为「湖州」（词库未收录的异地词保持原文，不强纠）。
- **AI 超时/失败**：纠偏或分镜决策超时必须如实降级（词库确定性纠偏 / 关键词匹配规则）并在引擎标识中标注降级链，严禁静默吞错或假装成功（真实执行铁律）。
- **空素材库**：某分类下无任何空镜素材时，对应分镜决策自动跳过并在理由中注明「该分类暂无素材」。
- **时间戳边界**：空镜时长不得超过句子时长；句尾与下一句起始的重叠区间不允许出现双画面。
- **旧数据兼容**：迁移必须幂等可重跑；`storage/legacy/` 归档原则遵循 004 决策修订记录。

## Requirements *(mandatory)*

- **IR1** 工具栏仅保留一个主动作按钮，文案「智能剪辑」；删除「单步纠错」按钮及其独立请求入口的前端调用（后端 `/correct` 端点保留供 API 兼容）。
- **IR2** 高亮词 = 词库命中 ∪ AI 判定 ∪ 手动编辑，三者合并去重并保留来源标记；持久化于 `SubtitleSegment.highlight_words`（含来源）。
- **IR3** 分镜决策输出必须为严格 JSON，包含 id、broll 分类、时长、转场时长、理由；越界值按约束裁剪。
- **IR4** 转场只切画面：合成管线音频始终取口播原始音轨（现有 `map 0:a` 行为保持）。
- **IR5** 分类更名 medical→experience 需 SQLite 表重建迁移 + 实体/词库/前端标签同步 + 幂等脚本。
- **IR6** 标题/水印默认关闭仅影响新建工程默认策略。
- **IR7** 封面字段进入工程模型与 API 契约；AI 生成入口为占位提示。
- **IR8** 修复 `codex.py` CLI 回退路径 `active_model` 未定义的 NameError（规划期代码审计发现的真实缺陷）。
