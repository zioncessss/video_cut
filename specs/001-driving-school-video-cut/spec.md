# Feature Specification: 驾校短视频网感剪辑工作台 (C-End Harness Video Cut Workbench)

**Feature Branch**: `001-driving-school-video-cut`  
**Created**: 2026-09-15  
**Status**: Draft / Under Review  
**Target Delivery**: 驾校招生推广短视频自动化生产套件（口播声画解耦 + 语义空镜替换 + ASR+LLM 校正 + 双端免终端启动）

---

## 1. 业务背景与定位 (Context & Vision)

当前 codex、zcode 等 harness 核心引擎偏向技术底层与开发者视角。本项目旨在：
1. **套壳 C 端化**：为 harness 提供轻量、高颜值、易操作的 Web/桌面交互界面，让驾校招生团队与非技术人员能零门槛使用。
2. **免终端启动**：跨平台适配 Windows 与 macOS，无需通过命令行黑框启动，开箱即用。
3. **聚焦驾校网感营销**：借鉴“开拍”等移动端网感剪辑逻辑，支持“口播讲政策/价格/场地 + 对应时间自动切空镜画面（声画分离 J/L Cut）”，并强化批量剪辑与并发资源调度能力。

---

## 2. 用户场景与测试用例 (User Stories & Acceptance)

### User Story 1 - 基础素材上传与四分目录管理 (Priority: P1)
作为驾校短视频运营人员，我希望上传各类原始视频片段，系统自动分类存入指定物理目录，便于系统调度与人工管理。

- **为什么是 P1**：所有后续 ASR、空镜替换与视频合成的前提是结构化的素材库。
- **独立验证方式**：用户在 Web 页面分别拖拽上传“口播”、“场地”、“体检”、“教学学车”4 类视频，确认文件正确保存到本地对应目录，并在界面生成元数据卡片。
- **验收场景**：
  1. **Given** 用户在素材管理页，**When** 拖拽一批视频到“场地视频”区域，**Then** 文件保存到 `storage/materials/venue/`，列表显示视频时长、分辨率与预览。
  2. **Given** 用户上传损坏或非视频格式文件，**When** 提交上传，**Then** 界面友好拦截并提示格式错误，不发生崩溃。

---

### User Story 2 - 口播音频 ASR 识别与 LLM 语义纠错 (Priority: P1)
作为视频创作者，我希望口播视频中的语音能高精度转化为带时间戳的字幕，并通过 LLM 纠正驾校专用术语错别字。

- **为什么是 P1**：字幕是决定视频网感和关键词匹配命中的基石，错别字会导致关键词匹配失效和用户体验骤降。
- **独立验证方式**：上传一段口播视频（包含“科目二”、“打方向盘”、“体检合格”、“包过/班型”等口语），对比原始 ASR 结果与经过 LLM 纠偏后的文字准确率。
- **验收场景**：
  1. **Given** 上传口播视频，**When** 触发字幕识别，**Then** Whisper/ASR 提取出带有起始-结束时间戳的字句列表。
  2. **Given** ASR 产生了“科尔”（应为“科目二”）或同音错字，**When** LLM 校正阶段执行，**Then** 结合驾校上下文精准替换为“科目二”，保留精准时间区间。

---

### User Story 3 - 关键词驱动空镜智能替换（声画分离 J/L-Cut） (Priority: P1)
作为视频剪辑师，我希望口播中提到“训练场/场地”时画面切到场地空镜，提到“体检”切到体检空镜，提到“教练/练车”切到学车空镜，而口播声音保持连续不中断。

- **为什么是 P1**：这是仿“开拍”网感剪辑的核心能力，彻底替代人工繁琐的多轨打点下料。
- **独立验证方式**：合成一段视频，验证特定时间区间内音频始终是口播声音，画面在对应关键词区间自动无缝平滑切至指定素材。
- **验收场景**：
  1. **Given** 口播在 00:05~00:09 提到“我们自建了五万平标准化训练场”，**When** 自动匹配空镜，**Then** 该区间画面从口播切换为 `venue` 目录中的随机场地素材，声音保持口播连续。
  2. **Given** 某分类下存在多个空镜素材，**When** 批量处理或生成，**Then** 随机抽取不同素材切片，确保生成的每个视频画面丰富度各异。

---

### User Story 4 - 交互式可视化预览与双轨字幕编辑器 (Priority: P2)
作为运营人员，自动生成的视频可能有个别文字或切点不理想，我希望在一个界面中直观预览并随手微调。

- **为什么是 P2**：提供 C 端产品必备的“人工接管与纠偏能力”。
- **独立验证方式**：在编辑器中修改右侧列表的某句字幕文字或时间，左侧播放器画面与字幕实时联动响应。
- **验收场景**：
  1. **Given** 进入 `/editor` 工作台，**When** 界面加载，**Then** 左侧为主播放器（带动态字幕），右侧为时间区间字幕卡片列表，底部为快捷修改文本框。
  2. **Given** 用户点击右侧某条字幕卡片，**When** 播放器跳转至对应时间点，用户修改文本内容，**Then** 播放器内字幕即时更新，并可重新渲染预览。
  3. **Given** 用户在底部文本框输入指令（如“把第3句空镜换成另一个场地素材”），**Then** 系统快速重新局部渲染该段素材。

---

### User Story 5 - 批量合成与硬件感知并发优化 (Priority: P2)
作为驾校多账号矩阵运营，我需要一次性批量生成 10~50 条视频，同时不让电脑死机卡顿。

- **为什么是 P2**：批量化是实际业务量产的核心诉求，也是体现工程调优价值的关键点。
- **独立验证方式**：添加 10 个视频生成任务，观察系统资源估算机制与任务队列调度。
- **验收场景**：
  1. **Given** 用户提交 20 条批量剪辑任务，**When** 系统开始处理，**Then** 首先探测本机 CPU 核心数、可用物理内存及 GPU 硬件加速通道（NVENC / VideoToolbox / QSV）。
  2. **Given** 内存或 CPU 占用达到预设阈值（例如安全水位 75%），**When** 调度并发任务，**Then** 动态将并发 FFmpeg 进程数控制在合理范围（如 2~4 个），后续任务平稳排队，UI 实时展示总体进度与耗时预估。

---

### User Story 6 - 双端免终端启动与 Harness 抽象解耦 (Priority: P3)
作为小白用户，双击应用图标即可在 Windows 和 Mac 电脑上直接打开，无需打开 Terminal / PowerShell 执行命令行。

- **为什么是 P3**：支撑 C 端软件定位，确保非技术人员开箱即用。
- **独立验证方式**：在 macOS 生成 `.app` / `dmg`，在 Windows 生成 `.exe` / 便携启动器，双击即可唤起主界面，后端 harness 自动就绪。
- **验收场景**：
  1. **Given** 用户双击桌面应用，**When** 启动完成，**Then** 直接展示浅色现代 UI 界面，后端 Harness 代理服务静默就绪。
  2. **Given** 底层 Harness 从本地自研引擎切换为 codex 或 zcode，**When** 在设置页面切换适配器，**Then** 上层剪辑业务流与 UI 无感知平滑运行。

## 3. 边界异常处理 (Edge Cases)

1. **口播无声或极微弱噪音**：ASR 返回空或置信度极低时，弹出明确告警：“未检测到有效口播语音，请确认视频音频正常”。
2. **某分类素材缺失**：若口播识别到了“体检”，但体检素材库为空，降级策略为“继续保持口播人像画面”，并在界面提示缺少素材。
3. **空镜素材时长短于关键词区间**：当选取的空镜只有 2 秒，但口播提及区间有 4 秒时，支持循环播放（loop）或画面平滑慢放/自动拼接下一个空镜。
4. **长文本并发 OOM 防御**：批量生成时若显存/内存吃紧，自适应降级为“单任务串行队列模式”，避免进程被操作系统 OOM Killer 强杀。

## 4. 功能需求清单 (Functional Requirements)

| 编号 | 需求描述 | 关联模块 | 优先级 |
| :--- | :--- | :--- | :--- |
| **FR-001** | 支持上传并管理 4 类素材：口播 (`talking_head`)、场地 (`venue`)、体检 (`medical`)、学车教学 (`lesson`) | 素材管理 | P1 |
| **FR-002** | 素材上传自动分类保存至独立磁盘目录，并提取视频分辨率、时长、帧率等元数据 | 本地存储 | P1 |
| **FR-003** | 口播视频一键提取音轨并执行 ASR 语音识别，输出带精确起始与结束时间戳（毫秒级）的文字片段 | ASR 引擎 | P1 |
| **FR-004** | ASR 文本自动提交至 LLM 进行上下文语义纠错，重点纠偏驾校特定术语同音字，并保持时间戳对齐 | LLM 纠偏 | P1 |
| **FR-005** | 关键词规则匹配系统：内置驾校规则库（地点、价格、场地、体检、科目二三练车等），匹配时间区间 | 剪辑策略 | P1 |
| **FR-006** | FFmpeg 复合滤镜管道：口播原声音频轨持续，指定关键词区间画面平滑平替为空镜头画面（J/L-Cut） | 视频渲染 | P1 |
| **FR-007** | 双栏响应式工作台：左侧 9:16/16:9 播放器（动态带字幕），右侧字幕与时间轴列表，底部指令框 | 界面交互 | P1 |
| **FR-008** | 用户可直接编辑任意字幕文本，并可拖动/微调该句的起始与终止时间，播放器实时定位预览 | 字幕交互 | P2 |
| **FR-009** | 硬件资源智能探测器：检测当前 CPU/RAM/GPU 可用资源，计算最优并发渲染进程数 | 资源优化 | P2 |
| **FR-010** | 批量视频生成队列：支持一次性配置生成多条视频，随机镜头混剪防重，提供整体与单项进度条 | 批量模块 | P2 |
| **FR-011** | 统一 Harness 适配器层：支持集成 Codex / Zcode / Local Harness，隔离前后端协议 | 架构解耦 | P2 |
| **FR-012** | 跨平台桌面级启动方案：支持 macOS 与 Windows 双击即开，无终端命令行暴露 | 部署封装 | P3 |

## 5. 非功能需求 (Non-Functional Requirements)

1. **视觉美学规范**：
   - 界面严格遵循 **现代浅色调（Light Theme）**，背景为 Clean Neutral 浅灰白（如 `#F8FAFC` / `#FFFFFF`），主强调色采用富有活力的智能蓝（如 `#2563EB`）或清新薄荷青。
   - 字体与排版采用高质感抗锯齿字体，卡片式设计配合微投影（Subtle shadow）与圆角（Rounded corners）。
2. **启动与响应性能**：
   - 客户端冷启动时间不超过 3 秒。
   - 字幕文本修改与本地预览播放器同步延迟小于 100ms。
3. **代码与架构质量**：
   - 遵循 KISS 原则（Keep It Simple, Stupid），杜绝深层无用继承与死循环轮询。
   - 管道执行采用事件驱动（Event-Driven）与流式通知，释放资源句柄。
