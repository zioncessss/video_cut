# Feature Specification: 重新合成性能提速与粗剪幽灵碎片跳剪根治 (017-recompose-speed-and-orphan-prune-fix)

**Feature Branch**: `017-recompose-speed-and-orphan-prune-fix`  
**Created**: 2026-10-16  
**Status**: In Progress  
**Input**: 解决视频裁剪后动作跳动/零散幽灵碎片残留问题，并彻底解决重新合成耗时过长、性能偏慢的底层瓶颈。

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 彻底消除裁剪遗留的废动作碎片与跳剪 (Priority: P1)

用户在剪辑台中手动删除了前置口误句（例如连续删除了第 1 句和第 2 句）或中间的重复句。在重新合成视频后，成片开篇平稳自然、直接进入真正保留的第一句台词，不再出现任何 0.3~0.6 秒的无字幕肢体晃动或手势突变跳剪。

**Why this priority**:
这是短视频剪辑的核心质量底线。如果裁剪后遗留 0.5 秒“幽灵碎片”，会导致画面闪现废镜头并剧烈跳切，严重损坏成片观感。

**Independent Test**:
加载带有连续被删除字幕的视频（如 `湖州驾校大改革`，删除第 1 句 0.80~2.24s 与第 2 句 2.76~3.54s）：
- 验证计算出的 `kept_spans` 不再包含 `2.24 ~ 2.76`（0.52s 废片段）；
- 验证成片从保留的第一句（3.54s）平稳起播，成片总时长精确缩短 0.52 秒，开篇无肢体瞬移。

**Acceptance Scenarios**:
1. **Given** 用户连续标记删除了两条或多条相邻字幕，**When** 粗剪引擎计算保留区间时，**Then** 相邻被删字幕之间的静音/换气间隙（无论时长 0.3s 还是 0.8s）自动被连带裁除，绝不作为有效画面残留。
2. **Given** 视频开篇存在一条或多条被标记删除的字幕，**When** 计算头部静音（Head Idle）切除时，**Then** 头部基准严格以“全片真正保留的第一条有效字幕”为唯一锚点，其前方所有的废动作与口误片段被一刀切净（仅保留 0.10s 自然起音气口）。
3. **Given** 粗剪引擎计算出的任何有效保留区间（KeptSpan），**When** 该区间时长小于 0.60 秒且其上没有任何有效字幕时，**Then** 系统自动将其识别为“无声幽灵碎片（Ghost Clip）”并彻底吸收剔除。

### User Story 2 - 重新合成链路极速提速与单次合成通道 (Priority: P1)

用户在剪辑台对分镜空镜、裁剪点、倍速或字幕进行调整后点击「重新合成」，系统能以最快的速度完成高质量成片生成。当修改了分镜/空镜导致底包缓存穿透时，不再经历“先压无字幕底包、再压字幕成片”的两次全量重编码折磨，而是在单次 FFmpeg 会话中直接产出最终视频；同时消除 CPU 纯软滤镜对 GPU 编码器的拖拽。

**Why this priority**:
剪辑是一个高频反复调试的过程。如果每次调整分镜都要等待 40~60 秒，创作体验极其糟糕。消除双重编码并优化滤镜能将合成耗时降低 50% 以上。

**Independent Test**:
在一个包含 3 个画中画空镜与粗剪切片的 30 秒工程中：
- 调整空镜时长后点击「重新合成」；
- 监控后台进程：仅启动一次核心 FFmpeg 压制会话；
- 验证成片在 8~12 秒内合成完成，画质清晰、字幕完整、音视频完全同步。

**Acceptance Scenarios**:
1. **Given** 分镜、空镜或粗剪切片发生变更导致无字幕底包未命中，**When** 执行 `render_project` 时，**Then** 系统采用单次直出合成通道（Single-Pass Render），将切片、空镜、调色与最新 ASS 字幕合并在单次 FFmpeg 编码中完成，同时写盘成片与底包缓存，严禁进行二次全量重编码。
2. **Given** 视频处于日常剪辑预览的重新合成阶段，**When** 执行画面缩放与调色滤镜时，**Then** 采用高吞吐自适应缩放算法（默认优先轻量抗锯齿高保真算法），避免单个 CPU 线程被高算力磨皮滤镜撑满导致 GPU 显卡空转，确保显卡硬件编码器帧率稳定在 100+ fps。
3. **Given** 工程挂载了多个空镜素材，**When** 组装 FFmpeg 命令前，**Then** 异步并发或复用素材元数据缓存完成规格检测，避免串行启动多个 `ffprobe` 子进程阻塞事件循环。

### User Story 3 - 存量工程无损自愈与向后兼容 (Priority: P2)

对于已经存在幽灵碎片或旧版切片时间轴的存量工程，无需用户重新转写或重新导入素材，重新打开或触发重新合成时自动完成切片自愈。

**Why this priority**:
保护用户现有数据，确保现有损坏案例立刻修复，避免遗留数据污染。

**Independent Test**:
对数据库中现存的 `54d31b37-5a5c-4664-b62a-e891a9dbc3d7` 工程执行重新切片计算：
- 断言其 `prune_spans` 与 `compact_subtitles` 自动修复；
- 断言第一条字幕时间戳从 `00:00.52` 自动归零回到 `00:00.00` 左右。

**Acceptance Scenarios**:
1. **Given** 数据库中现存工程有跨句幽灵碎片，**When** 服务端加载或同步粗剪时，**Then** 自动清洗幽灵碎片并更新紧凑时间轴，前端无缝呈现修正后的干净时间线。

## Functional Requirements *(mandatory)*

- **FR-001**: 粗剪引擎在合并剔除区间（`_merge_and_sort_spans`）时，将默认相邻吸附阈值由 `0.35s` 提升至 `0.65s`，并专门针对连续手动删除字幕实现无间隙闭包桥接（Prune Gap Bridging）。
- **FR-002**: 头部废动作（Head Idle）检测必须以 `sub.is_pruned == False` 的**第一个真正有效保留的字幕**为前瞻锚点；若前 N 条字幕均被剔除，头部剪切区间必须直接延伸覆盖至该保留句的起始点减去起音安全气口。
- **FR-003**: 保留区间反向计算（`compute_kept_spans`）后必须增加幽灵碎片过滤防线：凡时长 `< 0.60s` 且区间内无任何有效字幕字词重合的保留块，必须自动合并入相邻剔除区。
- **FR-004**: 重构 `render_project` 决策分支：当底包未命中（Tier 3）时，直接调用集成 ASS 字幕与横幅的单次合成流水线，一次性输出最终成片，消除两次全片重编码的耗时翻倍问题。
- **FR-005**: 滤镜管线在日常预览合成时优化算法开销，防止纯 CPU 单线程运算卡死 GPU 硬件编码器管道。

---

## Success Criteria *(mandatory)*

1. **零幽灵碎片与零跳剪率**: 在包含前置多句删除、中段多句连续删除的场景中，保留片段中时长 `< 0.60s` 且无字幕的废动作残留率为 **0%**。
2. **重新合成性能翻倍**: 在分镜或切片修改后，30秒口播视频的重新合成总耗时从原先的 **35~55 秒缩减至 15 秒以内**，耗时降低 50% 以上。
3. **字幕微调毫秒级保留**: 纯字幕修改场景维持底包秒级极速复用（1~2 秒完成）。
4. **全量测试通过**: 包含现有 314 项单测与新增粗剪防跳剪用例全量保持 100% 绿灯。
